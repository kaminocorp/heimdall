## Issue 1 — Authorization Gap on Per-App Endpoints (FIXED)

**Severity: Medium-High (security)**

Added `authorizeApp` helper to `applications.go` that every `{appId}` handler now calls. The helper uses a new `GetApplicationByOrgUser` sqlc query that JOINs `applications` with `users` on `org_id`, ensuring the authenticated user can only access apps within their own organization.

**Changes:**
- `backend/internal/db/queries/applications.sql` — Added `GetApplicationByOrgUser` query with `sqlc.arg` named params
- `backend/internal/db/applications.sql.go` — Regenerated by sqlc
- `backend/internal/api/handlers/applications.go` — Added `authorizeApp` helper; refactored all 6 per-app handlers (`GetApplication`, `GetAppAgentConfig`, `UpdateAppAgentConfig`, `GetMonitoringStatus`, `GetAppDashboardStats`, `ListConnectionsByApp`) to call it
- `backend/internal/api/handlers/applications_test.go` — Added `TestGetApplication_WrongOrg` test covering cross-org access denial on GET app, GET agent config, and GET monitoring status

## Issue 2 — Onboarding Handler Is Not Transactional (FIXED)

**Severity: Low**

Wrapped the 4 sequential queries in `Onboard` (`CreateOrganization`, `SetUserOrg`, `CreateApplication`, `UpsertAppAgentConfig`) in a database transaction using `pool.Begin` + `s.Queries.WithTx(tx)`. All operations now commit atomically; any failure triggers a rollback via `defer tx.Rollback()`.

**Changes:**
- `backend/internal/api/handlers/organizations.go` — Wrapped onboarding in `tx` with `qtx := s.Queries.WithTx(tx)`, added explicit `tx.Commit()`

---

## Issue 3 — Monitoring Prompt Uses Verbose Variant (FIXED)

**Severity: Low**

Replaced the verbose Variant A monitoring prompt with the token-optimized Variant B. The new prompt enforces a strict output format (`Severity: <level>`) that `parseSeverityFromResponse` can reliably parse, includes a decision tree for false-positive short-circuiting, and uses fewer tokens per call.

**Changes:**
- `backend/internal/agent/prompt.go` — Replaced `monitoringSystemPrompt` with Variant B
- `backend/internal/agent/monitor_test.go` — Updated `TestBuildMonitoringPrompt` assertions to match new prompt content

---

## Issue 4 — No Input Size Bound on Flagged Logs Sent to LLM (FIXED)

**Severity: Low**

Added two bounds to prevent runaway cost:
1. **Per-payload truncation** — Each log's raw payload is capped at 2000 chars in `formatFlaggedLogs`, with `... [truncated]` appended
2. **Batch cap** — If more than 50 logs are flagged in a single cycle, only the first 50 are sent to the LLM (with a warning log)

**Changes:**
- `backend/internal/agent/monitor.go` — Added `maxFlaggedForLLM` (50) and `maxPayloadChars` (2000) constants; truncation logic in `formatFlaggedLogs`; batch cap before LLM escalation
- `backend/internal/agent/monitor_test.go` — Added `TestFormatFlaggedLogs_TruncatesLargePayload`

---

## Issue 5 — Semaphore Can Block the Tick Loop (FIXED)

**Severity: Informational**

Added a 2-minute `context.WithTimeout` per `monitorApp` goroutine in `monitorTick`. This ensures that even if a Claude API call hangs, the goroutine will be cancelled and the semaphore slot released. The Claude SDK respects context cancellation, so this propagates cleanly.

**Changes:**
- `backend/internal/agent/monitor.go` — Added `monitorAppTimeout` (2min) constant; wrapped `monitorApp` call in deadline-scoped context
